# 온디바이스 자세 검출 검증

검토일: 2026-10-19. 현재는 기술 검증 구현이며 골프 지표 정확도 검증·출시 판정이 아니다.

## 선택과 근거

MediaPipe Pose Landmarker Full float16 v1, JS SDK `@mediapipe/tasks-vision@0.10.35` 고정 버전을 사용한다. 전신 33개 관절·영상 API가 제공되고 공식 웹 환경에 Safari가 명시되어 있다. 이는 iPhone 13 Pro에서의 속도나 골프 자세 정확도를 보장하지 않는다.

별도 서버 추론 비용 없이 기기에서 실행한다. SDK는 지연 로딩하고 모델과 WASM은 실행 시 Google Storage·jsDelivr에서 내려받는다. 오프라인은 지원하지 않는다. 모델의 로컬 재배포와 캐시 최적화는 별도 검증 후 진행한다.

대안: TensorFlow.js 계열은 모델·백엔드 통합 검증 범위가 추가된다. 네이티브 전용 추정은 PWA 우선 순서에 맞지 않는다. 기존 프로젝트에 자세 추정 의존성이 없어, 우선 공식 영상 API가 있는 단일 SDK로 검증한다. 모델 크기·실제 성능 비교는 미완료다.

## API·처리 방식

- 설치된 `vision.d.ts`의 `createFromOptions`, `detectForVideo(frame, timestamp)`, `close` 확인.
- 영상 길이·시간 탐색을 검사하고 5fps로 프레임을 읽는다. 최대 30초 촬영, 2분 처리 제한.
- CPU 추론·최대 1명·분할 마스크 비활성화. 검출 임계값은 기본 0.5. SDK 0.10.35의 module WASM 로더·바이너리와 OffscreenCanvas를 사용한다. Worker·OffscreenCanvas·createImageBitmap 미지원 시 실패 안내하며 메인 스레드 추론으로 자동 전환하지 않는다.
- 주요 관절 가시성: 코·양 어깨·양 손목·양 골반·양 발목이 화면 안이고 visibility 0.6 이상인 프레임 수. 임시 휴리스틱이며 스윙 점수가 아니다.
- 영상 메타데이터·시간 탐색·ImageBitmap 생성은 메인 스레드, SDK 초기화·CPU 추론은 전용 Worker에서 수행한다. 한 번에 한 프레임만 전송하고 처리 후 비트맵을 해제한다. 영상 디코딩 비용 자체는 별도 성능 검증이 필요하다.
- 취소·시간 초과·오류·정상 완료 시 전용 Worker를 종료한다. 영상 탐색의 이벤트 리스너·타이머도 정리한다. 프레임 응답은 15초, 초기화는 90초, 전체 작업은 2분 제한이다.
- 자세 0건도 정상 검증 결과로 표시한다. 결과·영상 업로드·DB 저장 없음.

전신·손목이 보이고 사람 1명만 등장하며 카메라가 고정된 밝은 환경부터 검증한다. 정확도 오차 허용치는 실제 기준 영상 비교 후 확정한다.

## iPhone 13 Pro 검증 절차

1. HTTPS에서 Safari 버전·iOS 버전·촬영 방향·조명·클럽·영상 길이를 기록한다. 정면과 측후방을 각각 준비한다.
2. 5초·15초·30초 영상의 첫 모델 로딩과 재실행 시간을 각각 기록한다. 발열·UI 정지·메모리 문제·최초 다운로드 실패도 기록한다.
3. 전신 정상·손목 가림·발목 이탈·사람 없음 조건에서 검출 프레임과 가시성 충족 프레임을 비교한다.
4. 다운로드 중 네트워크 차단, 분석 취소·재시도, 다음 촬영, 페이지 이탈을 확인한다. 이전 결과가 새 영상에 섞이지 않는지 확인한다.
5. 네트워크 검사로 영상 업로드가 없는지 확인한다. SDK 버전 변경 시 텔레메트리와 외부 요청도 다시 확인한다.
6. 후속 지표 구현 시 동일 영상의 수동 구간 표시·비교 장비·반복 분석을 이용해 지표별 오차를 기록한다.

실기기 결과: 미실행. 사용자 테스트 영상·기기 접근 없이 완료 처리하지 않는다.

## 실험 지표 motion-2d-v1 (2026-10-19)

현재 출력은 스윙 구간을 자동 식별한 골프 지표가 아닌 적용 구간 영상 평면의 변화다. 기본은 전체 영상이고 수동 시작·끝 시간으로 좁힐 수 있다. `motionMetrics.ts`는 SDK·브라우저에 의존하지 않는 계산 계약이며 실제 영상 정확도 검증은 미완료다.

- 머리: 코(0번)의 첫 프레임 대비 최대 2D 이동 / 첫 프레임 어깨 중점~골반 중점 길이. 화면에는 백분율 표시. 카메라 이동·피니시·얼굴 회전도 영향을 준다. 미터 환산 없음.
- 몸통: 어깨 중점~골반 중점 축과 화면 위쪽 수직축 사이의 부호 있는 각도를 구하고 첫 프레임 대비 최대 절대 변화 표시. 실제 척추각이나 3D 회전이 아님.
- x는 영상 폭 기준, y는 높이/폭을 곱해 같은 영상 평면 척도로 맞춘다. 렌즈·원근 왜곡 보정은 포함하지 않는다.
- 해당 관절 visibility 0.6 이상·유한값·화면 내부를 요구한다. 몸통은 위쪽 방향이고 폭 기준 길이 0.02 이상이어야 한다. 이는 임시 휴리스틱이다.
- 첫 샘플을 기준으로 하며 어드레스 여부를 자동 확인하지 않는다. 첫 샘플에 기준 관절이 없으면 늦은 프레임으로 대체하지 않고 측정 불가를 표시한다.
- 각 지표별 유효 샘플이 3개 이상이면서 전체의 70% 이상일 때만 제공한다. 이 기준은 측정 정확도를 보장하지 않는다.
- 템포·어깨 회전·좋고 나쁨의 평가 점수는 생성하지 않는다. 정식 스윙 지표는 구간 감지와 실제 영상 검증 후 확정한다.

### 수동 구간 선택 (2026-10-19)

- 시작·끝은 초 단위이며 `0 <= start < end <= duration`을 만족해야 한다. 구간 양 끝을 포함해 타임스탬프를 필터링한다.
- 5fps 샘플 중 구간 안의 첫 샘플이 기준이다. 입력 시각과 정확히 일치하지 않을 수 있어 실제 기준 시각·프레임 수를 함께 표시한다. 보간·자동 어드레스 감지는 없다.
- 3샘플 미만은 구간 적용을 거부한다. 첫 기준 관절 누락과 지표별 70% 커버리지 검사는 기존 규칙을 유지한다.
- 사용자는 영상 재생으로 시작·끝을 확인한 뒤 입력한다. 잘못된 입력은 안내하고 마지막 적용 결과를 유지한다. 전체 구간 버튼으로 복원한다.
- 최대 약 150개(30초·5fps)의 축약 자세 샘플만 메모리에 유지한다. 다음 촬영·페이지 종료 시 유지하지 않는다. 영상이나 샘플을 서버에 보내지 않는다.
- 새 분석·재촬영 시 입력·적용 상태를 초기화한다. iPhone의 실제 입력·영상 대조는 아직 검증하지 않았다.

## Worker 구현 검증 (2026-10-19)

- 설치된 SDK의 importScripts 실패 시 동적 import 대체 코드와 module WASM의 ModuleFactory 등록 방식을 확인했다. https://github.com/google-ai-edge/mediapipe/issues/5257 의 과거 모듈 Worker 문제를 고려했다.
- 요청·프레임 소유권 전송, 취소·늦은 응답 무시, 이미 취소된 비트맵 해제, 모델·Worker 오류 전달 단위 테스트 통과.
- 실제 브라우저의 WASM 초기화·OffscreenCanvas 추론·비트맵 전송은 미실행이다. 빌드 성공으로 Safari 호환 완료를 판정하지 않는다.
